# Seafarer — Contract & Finance Tracker

Локальный финансовый кабинет моряка на React 19, TypeScript, Vite, Tailwind CSS 4, Recharts, date-fns и ExcelJS. Русский интерфейс по умолчанию, английский переключатель, светлая и тёмная темы, адаптивная навигация для телефона. Платные сервисы, аккаунты и сервер не требуются.

## Разработка

Нужен Node.js 22.12+ (проверено на 24) и npm.

```sh
npm ci --cache /tmp/seafarer-npm-cache
npm run dev
```

Vite запускается на порту 5173. Откройте опубликованный адрес своего хостинга после развёртывания. В облачной среде проверяйте сервер локальным HTTP-запросом; встроенная ссылка предварительного просмотра не предоставляется.

```sh
npm test
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт `dist/`; `preview` обслуживает сборку на порту 4173. Исходники и lockfile не меняются при `npm ci`.

## Что работает

- Раздельные профили: контракты, счета, операции, заметки, цели и история.
- Редактируемый контракт с календарным сроком, ожидаемой и фактической датой списания, должностью, судном, компанией, зарплатой и методом расчёта.
- Календарь: навигация по месяцам, пройденные дни, сегодня, день списания, заметки и настроение.
- Реестр: зарплата, прочий доход, расходы, собственные категории, переводы между счетами, редактирование и удаление, будущие операции.
- Счета: начальные остатки, личный/семейный учёт, добавление, редактирование и сверка с корректирующей операцией.
- Прогнозы на сегодня, конец месяца, конец контракта и произвольную дату; предположения о расходах, доходах и месячном распределении накоплений.
- Цели и независимая оценка срока достижения; архив контрактов со сравнением судов, компаний, дней и заработка.
- Полный JSON backup/restore всех профилей; Excel с контрактами, дневными начислениями, операциями, счетами, отчётом и целями текущего профиля. Лист Backup содержит полную копию всех профилей для восстановления из собственного экспорта.
- Демо создаётся только по кнопке в настройках, в отдельном профиле с маркировкой ДЕМО.

## Расчёты и допущения

Даты — календарные `YYYY-MM-DD`; текущий день берётся из UTC. Зарплата начисляется за **завершённые** дни, сегодняшний день ещё не начислен. День посадки оплачивается; день списания по умолчанию **не оплачивается**. Оплата дня списания включается отдельно. Фактическое списание заменяет ожидаемую дату в расчётах. Три месяца от 18.10.2026 — 18.01.2027, 92 оплачиваемых дня при исключении списания.

Календарный метод: за каждый день `месячная зарплата / число дней в соответствующем месяце`. База 30: за каждый оплачиваемый день `месячная зарплата / 30`, включая 31-е число. Метод должен соответствовать условиям работодателя; приложение не определяет его автоматически. Суммы начислений округляются до цента после суммирования. Поля срока меняют дату автоматически, если очистить поле ожидаемого окончания при сохранении.

Полученная зарплата — реальные операции типа «Получена зарплата», привязанные к контракту. Начисленная зарплата — расчёт, она не меняет счёт. Личный баланс исключает счета, помеченные семейными; общий включает все. Внутренние переводы не считаются расходами. Внешние переводы семье отражайте расходом категории «Переводы семье».

Прогноз — сценарий, предполагающий получение всей ещё не выплаченной начисленной зарплаты к целевой дате плюс другой доход минус расходы. Это **не** фактический доступный остаток. Запланированные будущие операции видны в реестре, но не учитываются в текущих остатках и прогнозах: для прогноза используются отдельные предположения. Месячное накопление — распределение средств, не дополнительный расход; срок каждой цели оценивается независимо, без автоматического распределения общего бюджета между целями. Архив сохраняет параметры контракта, счета и операции продолжаются в профиле.

## Данные и безопасность

`localStorage` содержит данные только данного браузера и сайта. Синхронизации между устройствами нет. Очистка данных браузера может удалить записи. JSON и Excel включают финансовую информацию всех профилей: храните копии безопасно. Импорт полностью заменяет данные после подтверждения; сначала экспортируйте текущую копию. Импортируйте только доверенные файлы собственного экспорта. Приложение не отправляет финансовые данные на сервер, не содержит реальных персональных данных или ключей. Для будущей синхронизации выделен интерфейс `StorageAdapter` в `src/model.ts`; облачный адаптер должен отдельно реализовать аутентификацию, контроль доступа и разрешение конфликтов.

## Развёртывание

На Netlify / Cloudflare Pages / Vercel подключите репозиторий, задайте `npm ci && npm run build`, выходную папку `dist`, Node.js 24. Переменные окружения и секреты не нужны. Можно загрузить содержимое `dist` на любой статический HTTPS-хостинг. Клиентская маршрутизация без URL-путей, поэтому SPA rewrite не требуется. Для GitHub Pages в подпапке задайте `base: '/имя-репозитория/'` в Vite в отдельной задаче развёртывания или выполните `npm run build`, затем `npx vite build --base=/имя-репозитория/`. Для локального просмотра сборки используйте `npm run preview`.

## Проверки

`src/model.test.ts` проверяет переходы календарных месяцев, високосный февраль, обе базы зарплаты, фактическое списание, включение дня списания, ограничение дат, переводы, сверку, остатки, предоплаченную зарплату, изоляцию профилей и валидацию backup. `npm run build` проверяет типы всего интерфейса. Все примеры вымышленные.
